# 紫微斗數解讀 App — 規格文件（討論定案版）

> 狀態：規格已鎖定，尚未動工。最後更新 2026-08-29。

## 1. 目標
私人小工具，處理約 11 人的生辰資料，用 iztro 排出準確的紫微斗數命盤，再用 Claude 生成白話解讀（個性 / 盲點課題 / 流年 / 兩人比對）。

## 2. 技術棧（已實作）
> **免安裝架構**：這台機器沒有 Node，且安裝 Homebrew 受阻，因此改成**不需要任何建置步驟**的純瀏覽器 App。
- **Vue 3（含 runtime compiler，從 esm.sh 載入）**，元件用 template 字串，不用 .vue 單檔元件
- **iztro**（排盤引擎，從 esm.sh 載入；準確性已驗證）
- **扁平化 store**：`js/store.js` 用 Vue `reactive()`，一份人員名單 + 一份解讀快取（原規劃 Pinia，改為等效的輕量作法以減少 CDN 相依）
- **localStorage**：存人員資料、解讀快取、使用者的 API Key
- **解讀有三層，優先序由上而下**：
  1. **預先寫好的解讀（主要方式）**：`js/readings/person_XX.js`，key 格式同快取（`personality:person_01`）。使用者**點開分頁就直接看到內容**，不需要 Key、不需要複製貼上、不用等。這是使用者明確要求的體驗。
  2. 使用者自己存的版本（會蓋過預寫版）
  3. 以下兩種備援模式：
  - **免費模式（預設）**：App 組好完整提示詞（規則＋命盤 JSON）→ 使用者一鍵複製 → 貼到 Claude 網頁版 → 把回答貼回 App 存檔。不需 API Key、不花錢。
  - **API 模式（選填）**：設定裡填了 Key 才會出現「直接產生」按鈕，由 App 自動串流生成。因無打包步驟，直接用 `fetch` 打 Messages API 並自行解析 SSE。
- **執行方式**：雙擊 `啟動.command`（用內建 python3 起靜態伺服器並自動開瀏覽器）
- ⚠️ 第一次開啟需要連網（從 esm.sh 下載 Vue 與 iztro），之後瀏覽器會快取

## 3. 鐵則
- 星曜位置 **100% 來自 iztro**，Claude **只解讀、不得新增或更動任何星曜/宮位/四化**（system prompt 強制約束）。
- 引擎已驗證：Chloe(辛年)、kenny(壬年跨春節) 的四化/五行局/命身宮/農曆跨年皆正確。

## 4. iztro 用法備忘
- `astro.bySolar('YYYY-M-D', timeIndex, 'male'|'female', fixLeap, 'zh-TW')`
- timeIndex：0=早子(00-01) 1=丑 2=寅 3=卯 4=辰 5=巳 6=午 7=未 8=申 9=酉 10=戌 11=亥 12=晚子(23-24)
- palace 欄位：name, heavenlyStem, earthlyBranch, majorStars/minorStars/adjectiveStars（各星有 name, mutagen(化X), brightness）, decadal.range, isBodyPalace

## 5. 功能
1. **新增人**：姓名/性別/陽農曆/年月日時分/閏月 → 存 localStorage。內建 11 人預設。
2. **看個人**（單人深度報告，分頁）：命盤總覽 / 個性剖析 / 盲點與課題 / 流年運勢（預設當年，逐月另點且標「參考」）
3. **兩人比對**（簡單版）：個性互補/衝突，非專業疊盤合盤

## 7. 解讀 Prompt 設計

### 7.1 餵給 Claude 的資料契約（程式先算好）
除 12 宮星曜外，程式**預先算好**並標註：三方四正、四化飛入飛出、命/身/福德/遷移關鍵宮、選定年份的流年盤。Claude 只能用這包資料。

```jsonc
{
  "person": { "name","gender","solarDate","lunarDate","time" },
  "core":   { "命主","身主","五行局","命宮支","身宮位","age" },
  "keyPalaces": { "命宮":{主星,煞,三方四正:{財帛,官祿,遷移}}, "身宮":..., "福德":... },
  "四化":   [ {"星","類":"祿/權/科/忌","宮"} ],
  "煞星分布":[ {"星","宮"} ]
}
```

### 7.2 系統提示（共用）
- 角色：經驗老到、直言不諱的命理分析師，解讀「已排好」的盤。
- **鐵律**：只能用提供的 JSON；不得編造/新增任何星曜宮位四化；不得重新排盤；資訊不足就明說不腦補。
- **表達**：繁體中文、**完全白話、一個命理術語都不准出現**（化忌/三方四正/擎羊/廟旺/宮位名等一律翻成白話結論）。
- **語氣**：直白犀利，優缺點都講到痛點，不美化不繞圈，對事不對人。無開場白、無客套、**無免責聲明**。
- **未成年規則**：未滿 16 歲強制放軟——改用引導/教養角度，弱點講成「需要被好好引導的地方」並給父母教養建議，重點放天賦培養，語氣溫暖。（套用 person_03）

### 7.3 各功能指令
- **A 個性剖析**：本性(核心3特質)、天賦優勢。直接說。
- **B 盲點與課題**：致命盲點、性格弱點(不美化)、這輩子的功課。
- **C 流年運勢**：今年主軸一句話、機會、要當心什麼。（精簡2-3句/完整可展開含上下半年）
- **D 兩人比對**：合不合為什麼、爽點與雷點、各自要調整什麼。

## 8. Claude API 串接流程（已定案）
- **純前端呼叫**：Anthropic 直呼需帶 header `anthropic-dangerous-direct-browser-access: true`（Key 活在瀏覽器，符合自用模式）。
- **貼 Key UX**：無 Key 時跳設定框貼 `sk-ant-...` → 存 localStorage → 設定頁可換/清；401 時明確提示「Key 無效或額度不足」。
- **串流**：SSE 逐字打字機顯示（要）。
- **結果快取**（要，省錢核心）：命盤固定 → 個性/盲點算一次永久快取；流年每年一份快取；提供「重新生成」按鈕手動重跑（要）。
- **模型**：Claude Sonnet（最新 `claude-sonnet-5`；動工接 API 時用 claude-api 技能確認當下 model id 與價格，不憑記憶）。
- **錯誤處理**：Key 無效 / 額度用盡 / 斷網 / 回傳截斷，各給清楚中文提示。
